How it works

From SQL to a finished document in three steps

1

Design

Add a SQL data source, drag fields onto bands, format, preview with real data, publish.

select inv_no, customer, amount
  from invoices
 where id = :INVOICE_ID
2

Connect

Add the Print Report plug-in to a button and map page items to report parameters.

Action:  Docsmith - Print Report
Report:  INVOICE
Items:   P10_INVOICE_ID
Output:  Download PDF
3

Print, e-mail or store

Users click, the file arrives. Or call it from PL/SQL and jobs for bulk runs and e-mail.

l_pdf := rpt_api.get_document(
  'INVOICE', '{"INVOICE_ID":42}');

The render server runs on your Windows or Linux server, or in Docker. Reports, SQL and data stay in your Oracle database.

Questions teams ask

Which APEX and database versions are supported?

Oracle APEX 26.1 or later on Oracle Database 19c or later, on-premise or in the cloud (OCI, Autonomous Database with network access to the render server).

Where does our data go?

Nowhere outside your network if you host the render server yourself. The database sends one report’s data to it, it returns the file and keeps nothing.

Can we run the render server on Windows?

Yes. A ready Windows package installs as a service and uses the Edge or Chrome already on the server. Linux and Docker images are available too.

What happens when the trial ends?

Nothing breaks. PDFs get a TRIAL watermark and Word / Excel export pauses until you enter a licence key on the License page. No reinstall is needed.

Can we move our BI Publisher reports?

Most are rebuilt in Docsmith in less time than an RTF fix takes. Enterprise includes help with converting your existing reports.

Do test and UAT instances need their own licence?

No. Send us their Instance IDs and we add them to your production key.

Do you offer support and training?

Every paid licence includes updates and e-mail support. Enterprise adds an SLA, priority fixes and developer training.
